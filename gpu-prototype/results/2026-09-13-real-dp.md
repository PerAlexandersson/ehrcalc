# Real flagged-Kostka GPU comparisons on RX 9070 XT

Date: 2026-09-13

Hardware: AMD Radeon RX 9070 XT (`gfx1201`, 16 GiB) on Euler.

Software: ROCm 7.2.4 userspace container, rocPRIM 4.2.0, and `hipcc -O3
--offload-arch=gfx1201`. The host graphics driver was not replaced. Rust
release builds used the external Cargo target directory
`/mnt/2TB-Babel/ai-storage/cargo-target`.

sizes, but they are not end-to-end timings.

## End-to-end variants

The CPU-enumerated hybrid materializes transitions serially, uploads each
layer, and performs only aggregation on the GPU. The GPU-resident version uses
one thread per source state to count and emit horizontal-strip extensions, a
rocPRIM exclusive scan for offsets, and rocPRIM sort/reduce. States remain on
the device between labels.

| Dilation | CPU packed modular wall | CPU-enumerated hybrid | GPU-resident device/total | Container wall | Result |
|---:|---:|---:|---:|---:|---|
| 1 | <0.01 s | 0.213 s internal | 0.023/0.028 s | 0.50 s | exact residue 125,835 |
| 3 | <0.01 s | not run | 0.122/0.128 s | 0.56 s | exact residue 369,110,195 |
| 6 | 1.27 s | 2.022 s internal | 1.183/1.194 s | 1.63 s | exact residue 306,879,955 |
| 9 | 48.86 s | 67.676 s internal | 12.914/12.929 s | 13.37 s | exact residue 2,040,897,519 |

The useful comparison at dilation 9 is 48.86 / 12.929 = **3.78x** for the
algorithm-internal end-to-end times, or 48.86 / 13.37 = **3.65x** including a
fresh Docker process. The hybrid loses because its serial transition
materialization alone takes 66.628 seconds; its GPU aggregation work is only
0.547 seconds.

The dilation-9 resident run reached 243,369 states and 115,666,316 transitions
in its largest layer. At that layer the six full-sized key/value arrays require
about 6.94 GB and rocPRIM reported a 2.33 GB sort workspace, for roughly 9.27
GB before small state and scan buffers. This fits the 16 GiB card without
chunking. The largest layers are dominated by the count and emit kernels;
sorting is no longer the limiting phase.

## Independent residue and validation checks

The resident binary accepts a runtime modulus. At dilation 6 it matched the
Rust reference independently under the first two default primes:

| Modulus | CPU residue | GPU residue |
|---:|---:|---:|
| 2,147,483,647 | 306,879,955 | 306,879,955 |
| 2,147,483,629 | 1,629,530,989 | 1,629,530,989 |

Their product exceeds the stored exact dilation-6 count, and these two residues
reconstruct 157,798,415,095,915,566 by CRT. The first dilation-9 residue also
matches the stored exact count modulo 2,147,483,647. In addition, every state
count and transition count in the tested real layers matches the Rust trace.

`gpu-prototype/run-smoke.sh` covers two moduli on small skew, flagged, and
zero-strip examples. Rust separately tests exhaustive small skew counts,
flagged counts, layer sort/reduction, coprimality rejection, packing width, and
bounded CRT ambiguity rejection.

## Current boundary

This is a testable proof of concept, not yet Ehrcalc's production exact backend.

- The resident HIP executable currently carries one residue per pass. Exact CRT
  can be obtained by repeated passes, but bundling two or more lanes is needed
  to retain the measured speed advantage for large exact answers.
- Strict/interior flagged counting is not implemented in the packed modular or
  HIP paths yet.
- A layer that exceeds the configured transition cap aborts cleanly; chunked
  aggregation is not implemented.
- The executable targets `gfx1201` in the documented build command and has not
  been portability-tested on another AMD architecture.
- The production Rust API and CLI still use the maintained `BigUint` backend.

The result passes the planned 3x large-case performance gate. The next useful
engineering step is a two-lane resident value type, followed by certified CRT
reconstruction and strict/interior parity before any default-backend change.
